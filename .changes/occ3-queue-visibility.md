Added: optional, capability-gated `communicationQueue` roster metadata (schema 45, `agent_communication_queue`) projecting a content-free view of the sender's OCC-3 queue notices on active session rows, with per-entry position, receiver, state, attempts and both stable ids, plus a full `pendingTotal` and an explicit `omitted` count that survives the display bound.
Added: snapshot-form queue notices (one record carrying the full queue view) as the authoritative transcript base; individual notices newer than a snapshot override it and the scan stops at the newest snapshot, so reconstruction no longer depends on stale history depth (scan bound raised to 512 records for the individual-only form).
Added: `QUEUED n` advisory badge in the subagents bar beside the TXT/OCC1/OCC2/OCC3 pulse indicators, counting from the authoritative `pendingTotal`; pending queue entries never pulse (completed-use receipts remain the only pulse trigger).
Added: `/occ status` per-entry native handoff queue table (position, receiver, state, attempts, queue id, message id or an explicit placeholder while unminted) with an explicit `+N more queued` line; terminal states are fallback, failed, completed and expired, and the intermediate `fallback_pending` stays pending while rendering with the fallback label.
Added: the sender queue's frozen UI state labels (pending renders queued; published renders in-flight; admitted renders acknowledged — an honest transport acknowledgment, never consumed); unfinished re-emission renders "fallback (pending)" so users distinguish it from the terminal acknowledged fallback, the fallback rows state their ordinary-delivery verdict (delivered or queued) and the whitelisted manual resolution (manual re-emit or manual cancel) that drained an uncertain entry; the possibly-consumed "uncertain" state renders "uncertain (pending receipt)" and stays counted pending, never auto-resolved or TTL-expired; unknown states pass through unchanged so unrecognized states stay visible.
Changed: `DAEMON_SCHEMA_REVISION` 44 -> 45 (`protocol-7-schema-45-communication-queue`); roster commands and startup keep their existing compatibility floors; clients strip the field when the daemon does not advertise the capability.
Added: manual OCC-3 queue resolution (schema 46, `agent_communication_queue_control`): the optional, capability-gated `occ_resolve_queue_entry` session-plane command resolves one uncertain entry on the attached chat's own native queue — cancel (terminal `failed`, manual_cancel, never re-sent) or explicitly confirmed re-emit (fallback_pending with a fresh dispatch token riding the existing ordinary OCC-1 re-emission flow). The response is content-free (ids and state; the dispatch token never crosses the wire). The in-process connection resolves directly through the same AgentSession APIs; old daemons/clients degrade to guidance text, never an unknown command.
Added: `/occ queue cancel <id>` and `/occ queue reemit <id>`: dialog-confirmed manual resolution with the duplicate-delivery risk stated in the re-emit dialog itself; only the explicit proceed choice resolves anything, a dismissed dialog changes nothing, and non-uncertain entries are refused client-side before any send.
Added: `/occ status` and the roster projection now surface the whole-queue blocked state (whitelisted unsupported_schema, unreadable, unreadable_io from the newest snapshot notice), the newest enqueue refusal event (queue_full or queue_blocked; cleared only when entry-bearing notices recorded after it prove admission resumed, never by a snapshot alone), and the durable outbox overflow flag (noticeOverflow) — all content-free and never counted as queued work.
Changed: the bounded queue display list now gives live (non-terminal) entries the display slots first, ordered by position; terminal entries fill only the leftover slots newest-first; `omitted` counts only dropped PENDING entries, so a deep terminal history can neither crowd live work out of the list nor inflate the "+N more queued" line.
Changed: `DAEMON_SCHEMA_REVISION` 45 -> 46 (`protocol-7-schema-46-communication-queue-control`); a pre-46 daemon keeps answering every earlier command, the 45-era visibility capability never authorizes the resolution, and the roster `communicationQueue` field is unchanged.
