Added: a daemon restart inside the OCC-3 server permit window no longer leaves the resumed root session without the occ3_handoff tool. The server registry refuses a same-session re-enrollment while the previous daemon's permit is still live and prunes it only at expiry (bounded by the one-hour server TTL), so the worker-ready activation after a restart fails with install_refused and previously had no retry: the model-change hook was the only recovery path, leaving sessions that never switch models dark until another restart. The worker-ready site now arms the existing pending-activation marker with a restart-retry window (OCC3_ACTIVATION_RESTART_RETRY_WINDOW_SECS = 3700, one hour plus margin) when the refusal is transient (ModelIdentityMismatch from the same-session enroll refusal, or ConnectorUnavailable for a control plane not reachable at boot). The pre-prompt consumer re-arms the marker after a transiently refused retry only while the window is open, so recovery is prompt-paced inside the window and one-shot outside it, exactly like the model-change retry. Stable declines (not_configured, disabled_by_policy, ...) never arm anything.

Why: observed live on 2026-11-09 - the v0.1.44 daemon restart at 09:39:41Z fired worker-ready activation while the resumed session's first turn was streaming; enroll refused (install_refused) because the previous daemon's permit (minted 08:55:19Z) was still live; the session lost occ3_handoff and only recovered via a manual double model switch after the permit expired at 09:55:19Z.

Tests: two new wiring tests through the production add_runtime seam. restart_refusal_arms_windowed_activation_retry_until_it_clears starts the fixture session on the OCC-3 model with the enroll route refusing (fixture mode 3, the restart refusal), asserts the worker-ready path arms the marker with a window, asserts the consumer re-arms after a persistent refusal, then clears the refusal and asserts the activation lands with the handoff tool installed. expired_restart_window_clears_the_marker_after_a_transient_refusal forces the window into the past and asserts the one-shot semantics. The ModelChangeActivationFixture gained a build(start_on_occ3, first_enrollment_failure) parameterization; the existing non-OCC-3-start fixture path is unchanged.
