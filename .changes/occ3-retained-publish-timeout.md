Added: the retained publication leg of the native phase suite (`crates/pi-coding-agent/examples/occ3_native_phase_suite.rs`, `run_positive_case`) is now bounded by the case deadline. `publish_retained` runs inside `tokio::time::timeout(Duration::from_secs(env.deadline_seconds), ...)` - the same idiom the no-state control already uses for its receiver leg - because the isolated controller's receiver prompt has no internal envelope and a wedged publish or receiver route would otherwise hold the phase until the harness killed it. On expiry the elapsed deadline becomes the terminal action error `retained_publish_timeout` (a fixed sanitized tag; a matching `occ3-retained-publish-diag retained_publish_timeout deadline_seconds=<n>` stderr line follows the existing source-turn diag pattern, so live phase logs name the timeout without the pinned report fieldset changing), the flow still reaches `family.close()` (no early return sits between the assignment and the cleanup), and the one-shot publication claim taken before the first await in `publish_retained` is not released, so nothing can retry the publication.

Two offline regressions drive the real `run_positive_case` path (no stub controller) against a short wrapped deadline through a new `offline_trial_context_with_deadline` helper: the fixture gains strictly `#[cfg(test)]`-gated hang injections - `hang_receiver_turns` parks the receiver-turn route (discriminated by the occ3 attachment key; the capture-armed source route stays fast) and `hang_publish_route` parks the publication route on a latched `tokio_util::sync::CancellationToken`, each recording a `hang_events` entry, and `serve` registers every spawned per-connection task in a test-only registry so the tests own their cleanup (the production spawn stays fire-and-forget; the validator should also build the example with tests disabled to confirm the machinery compiles out). The teardown cancels the token first (held routes return and drop their sockets), aborts and awaits the accept task to termination before draining the registry (no late connection slips past the drain), then aborts and joins every tracked connection - all under ONE aggregate five-second cleanup deadline asserted on the happy path, with a sync-only Drop-guard backstop that cancels and aborts whatever is still registered if any step panics; the guard is armed as soon as the trial's resources are owned (before the connector unwrap and the case run), disarmed only after the successful teardown, and consumed by the teardown so ownership is single from construction to disarm. The accept task rides a shared test-only ownership slot: Drop aborts the occupant through the slot without taking it, while the teardown (or the unwind test's observer) takes it exactly once and awaits the actual termination. The dedicated unwind regression first awaits a latched route-arrival signal (set after the hang event is recorded, before the park) so the abort provably lands on a parked handler, then triggers Drop as the only cleanup and observes, test-owned: the token cancelled synchronously, the aborted accept task's actual termination (bounded join of the retained handle - never a join claimed from Drop itself), and the parked socket's bounded closure. The post-submission test asserts the sanitized tag in the arm evidence, case failure, `family.close()` cleanup recorded, no success receipt, exactly one publication POST and one receiver turn (one-shot, no retry), and the bound lease reading `Uncertain` in the receiver inbox audit after the dropped wire submission (the library-pinned drop transition); the pre-bind test asserts the same terminal shape with no inbox record at all (lease state null, no receiver turn). Timing assertions are semantic only (the wrapped deadline fully elapsed); the timeout tag and the joined bounded cleanup are the real evidence.

Scope: the suite example only - no library, connector, producer or support-module changes; the pre-existing early-return close-bypass on the retained turn-failure path is deliberately untouched (deferred hygiene, out of scope); no retry knob or fallback was added anywhere. The suite's offline pins (binary and manifest digests) are expected to move with this source change; re-pinning belongs to the validation runner.
