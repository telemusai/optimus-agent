Fixed: the OCC-3 native-handoff receiver framing now directs the receiving model to read the attached state as the primary information source and report its facts, codes, and numbers verbatim. A new `OCC3_CONTROL_SUMMARY` constant (`occ/occ3/types.rs`) carries the proven framing: it names the attachment position (the sender's latent rows are attached to the turn immediately after the control message) and requires character-for-character reporting without paraphrasing, completing, or guessing, while staying receiver-framed so the receiver answers as itself rather than in the sender's voice. The sglang connector's publication envelope now uses the constant in place of the previous vague one-liner, and the `PreparedNativeHandoff` binding check compares against the same constant, so publication and validation cannot drift apart; the `occ3_state` unit-test fixture constructs its envelope from the constant as well.

Why: differential forensics from the 2026-11-08 cross-machine drills. Windows receivers holding ~19.8k-token session contexts recovered the sender's facts only approximately across 5 drill legs: alphanumeric codes were garbled in 5/5 legs (prefix loss `OCC3-` -> `COPC`/`COPCC3`/`COPR3`, case loss, adjacent-token drift) and numbers were exact in only 4/5. The sender emission was byte-clean and the receiver's restatement was faithful, so the loss occurred while the receiver read the attached state under a framing that never instructed verbatim extraction. The Linux idle-parent round-1 control passed byte-exact under the proof-harness framing (explicit attachment position, verbatim-extraction instruction, `<<occ3-statebegin>>` markers); the constant carries those attachment-position and verbatim-extraction properties into the production envelope.

Files: `crates/pi-coding-agent/src/core/occ/occ3/types.rs` (new `OCC3_CONTROL_SUMMARY`), `crates/pi-coding-agent/src/core/occ3_connectors/sglang.rs` (publication envelope uses the constant), `crates/pi-coding-agent/src/core/agent_messages.rs` (binding check uses the constant), `crates/pi-coding-agent/src/core/agent_session/occ3_state.rs`, `crates/pi-coding-agent/src/core/agent_session/occ3_invalidate_triggers_tests.rs`, `crates/pi-coding-agent/src/modes/daemon/daemon_occ3_native_wiring_gap_tests.rs`, and `crates/pi-coding-agent/examples/occ3_native_phase_suite.rs` (every remaining hardcoded copy of the old one-liner - test fixtures, daemon wiring-gap fixture connector, phase-suite example - now uses the constant).
