Fixed: a transient send-phase transport failure of the enrollment control call no longer aborts the whole armed facts turn. The armed capture's `enroll` runs at the start of the facts turn (`prepare_source_capture` makes exactly one control call before building the lease), and a pooled connection reset by the gateway between reuse killed that call 0.35s after the capture armed, so the sender emitted "Experimental native handoff unavailable or uncertain; replay is forbidden" and the handoff died with a tombstone instead of a transport retry (live round-1 stability failure on client b2ae1805, 2026-11-08).

Fixed: `sessions/enroll` now retries send-phase transport failures up to twice with a 250ms delay and the byte-identical body. Enrollment is the one control route that is idempotent under an identical body: the registry keys its immutable per-session record on session_id and compares everything except operation_id, so a resend - even one whose first attempt reached the server - re-enrolls the same record. The same retry covers the re-enrollments inside `publish_native_source` (source + receiver, documented idempotent per session).

Fixed: every semantic decline keeps its first-occurrence classification. A decline that produced an HTTP response (busy 409, quota 429, authority 401/403, malformed payload) is never retried and never reclassified, and the bounded error-code read still only chooses the error kind. Send timeouts are deliberately not retried: a request that may still be in flight must not be duplicated blindly, and a hanging server still fails at exactly one HEALTH_TIMEOUT instead of multiplying it against the turn budget.

Added: three loopback wire-shape regressions in `sglang.rs`. `enroll_retries_a_transient_send_failure_and_enrolls` serves the exact live failure shape (request fully read, then the connection closed with no response at all) and proves the identical resend enrolls; `enroll_send_retry_exhaustion_fails_closed` proves exhaustion still fails closed with the existing `TransferFailed` after exactly 1+N attempts; `enroll_never_retries_an_http_decline` proves a 429 quota decline is sent exactly once and keeps the `NativeInferenceBusyRefused` classification. `native_binding_diagnostic("control", "send_transport_retry", ...)` makes each retry visible in the existing diagnostics channel with no new secrets or values.
