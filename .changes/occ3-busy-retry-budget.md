Changed: the OCC-3 sender-queue busy-retry budget and backoff schedule are operator-selectable instead of hardcoded. `OCC3_BUSY_MAX_RETRIES` (any u32 clamped to 1..=10, default 3) sets how many busy refusals a queued native handoff absorbs before falling back to ordinary OCC-1 re-emission; `OCC3_BUSY_BACKOFF_SECS` (comma-separated seconds, each clamped to 1..=30, default 2/4/8 with the last wait repeating past the schedule) sets the wait between busy retries. Both follow the existing `OCC3_SENDER_QUEUE_*` env-knob pattern: parsed through pure functions at refusal time, never persisted, unparseable values keep the default. Persisted-entry validation now bounds `busy_retries` against the hard limit (10) rather than the default budget, so a queue legitimately written under a raised budget still loads when the environment reverts.

Changed: every busy-retry prompt now interpolates the effective budget (arm prompts, receiver-busy and source-busy re-capture prompts), and the `occ3_handoff` tool description says "the configured busy-retry budget" instead of a hardcoded "3", so the model is never told a wrong ceiling. Server-provided `retry_after` hints still win over the schedule when present and bounded.

Why: with a wave of parallel child sessions inferring on one serialize-by-design deployment, every capture window can be declined for minutes while the default 3x2/4/8s window exhausts in ~15 s and the native transfer is lost to OCC-1 fallback (observed in a three-lane hive run on 2026-11-09: both setup handoffs fell back; the wrap-up handoff admitted only after all children went idle). Operators running hive-style waves can now raise the budget and stretch the schedule to match their wave duration instead of losing native transfer. Defaults are unchanged for single-sender use.

Tests: new `busy_knob_parsers_clamp_and_default` unit test pins the pure parser contract (defaults on empty/invalid, clamps at 1 and 10, schedule clamps at 1/30, junk parts drop, last wait repeats). `busy_fields_are_backward_compatible_and_bounded` now writes `OCC3_BUSY_MAX_RETRIES_LIMIT + 1` for the load-block case. Existing default-budget behavior tests (fallback after 3, prompt wording, backoff values) are unchanged and still pin the defaults.
