Fixed: a busy-refused receiver `prepare_inference` no longer wedges the receiver session permanently. The resolver claimed the earliest admitted inbox record before preparing, and any prepare failure left the record claimed/`Delivered`, so every later claim refused with `InferenceOutcomeUncertain` collapsed to the generic "Experimental native handoff unavailable or uncertain; replay is forbidden" string until a client restart (live 2026-11-07 parallel-handoff pair q1).

Fixed: the receiver now retires the busy-refused claim and runs the busy turn ordinary without the native attachment when - and only when - the refusal provably left this consume's attachment unsubmitted. `prepare_inference` awaits exactly one control call (sessions/enroll) before building the receiver attachment, and only a bound, submitted attachment can reach the provider, so a synchronous decline of that call proves the attachment was never created or submitted. On that route today the real decline is the saturation gate's `quota` (429: session-table capacity, or the pre-parse 16 KiB body bound). Enroll has no `busy` code - that is the registry's reserve_capture/reserve_consume admission decline - and the classification pairs the two so a future control route reusing the registry decline gets the same contract. The record retires as a terminal busy `Failed`: pre-notified, never re-claimable, never consumed, never a second delivery from this side. The sender is routed the same proven-non-use busy signal, so its in-flight admitted queue entry takes one bounded busy retry (2s/4s/8s backoff) and re-arms a fresh capture as the sole retry path. The receiver can never consume the retired handle while the sender's re-send is in flight, so the facts can never be delivered twice. The new `Occ3Error::NativeInferenceBusyRefused` error kind carries the class, and a bounded error-code read never trusts response text. The classification is the generic control-path rule, but only `prepare_inference`'s enroll error reaches the retire arm (publication/retirement keep their existing uncertain paths). Every other decline - including 409 `expired`/`replay` - keeps the fail-closed generic refusal with the claim held.

Fixed: genuinely-uncertain outcomes stay exactly fail-closed. `Occ3InferenceInbox::retire_busy_claim` retires only the exact claimed-unbound state between `claim` and `bind_lease`; a bound lease, a terminal status, an unclaimed or an unknown record never retires, so nothing is ever replayed and the generic uncertain error string is byte-identical to before.

Fixed: the busy-retirement diagnostic distinguishes a routed retirement from an orphaned one. `route_receiver_busy_to_sender` returns whether a live sender absorbed the signal, and `receiver_busy_claim_released` logs the retired message id, the refusing connector, `released`, and `sender_routed`, so a retirement whose route found no sender is visible instead of silent. The log name and `released` key keep the pre-rename wording for grep stability.
