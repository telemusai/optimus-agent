Fixed: a busy-refused receiver `prepare_inference` no longer wedges the receiver session permanently. The resolver claimed the earliest admitted inbox record before preparing, and any prepare failure left the record claimed/`Delivered`, so every later claim refused with `InferenceOutcomeUncertain` collapsed to the generic "Experimental native handoff unavailable or uncertain; replay is forbidden" string until a client restart (live 2026-11-07 parallel-handoff pair q1).

Fixed: the receiver now retires the busy-refused claim and runs the busy turn ordinary without the native attachment when - and only when - the refusal provably left this consume's attachment unsubmitted: `prepare_inference` awaits exactly one control call (sessions/enroll) before building the receiver attachment, and only a bound, submitted attachment can reach the provider, so a synchronous decline of that call proves the attachment was never created or submitted. On that route today the real decline is the saturation gate's `quota` (429: session-table capacity, or the pre-parse 16 KiB body bound); enroll has no `busy` code - that is the registry's reserve_capture/reserve_consume admission decline - and the classification pairs the two so a future control route reusing the registry decline gets the same contract. The record retires as a terminal busy `Failed` (pre-notified, never re-claimable, never consumed, never a second delivery from this side) and the SENDER is routed the same proven-non-use busy signal, so its in-flight admitted queue entry takes one bounded busy retry (2s/4s/8s backoff) and re-arms a FRESH capture as the sole retry path - the receiver can never consume the retired handle while the sender's re-send is in flight, so the facts can never be delivered twice. The new `Occ3Error::NativeInferenceBusyRefused` error kind carries the class; a bounded error-code read never trusts response text; the classification is the generic control-path rule but only `prepare_inference`'s enroll error reaches the release arm (publication/retirement keep their existing uncertain paths); and every other decline - including 409 `expired`/`replay` - keeps the fail-closed generic refusal with the claim held.

Fixed: genuinely-uncertain outcomes stay exactly fail-closed. `Occ3InferenceInbox::release_busy_claim` releases only the exact claimed-unbound state between `claim` and `bind_lease`; a bound lease, a terminal status, an unclaimed or an unknown record never releases, so nothing is ever replayed and the generic uncertain error string is byte-identical to before.

Fixed: a busy-released turn no longer risks silent handoff loss. The receiver's control-only transcript body carries no source facts, and the retired record is never re-claimable, so without a route the facts would be lost with no error. The release routes the same proven-non-use busy signal the TurnEnd dispatcher uses for refused leases to the sender's queue: the in-flight admitted entry takes one bounded busy retry (2s/4s/8s backoff) and re-arms a fresh capture, which becomes the sole retry path for those facts. Terminal retirement plus the sender route makes the two retry paths mutually exclusive: the receiver cannot consume the retired handle while the sender's re-send is in flight, so the same facts can never be delivered twice.

Fixed: live diagnosis of a busy-released turn no longer needs source archaeology. Each release emits one content-free `receiver_busy_claim_released` diagnostic (message id, connector id, released flag) in the connector-diagnostics style; a broken log sink can never turn a released claim into a failed turn.
