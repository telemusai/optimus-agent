Added: `crates/pi-coding-agent/examples/occ3_native_proof_transport.rs`, the PHASE 1 offline Windows component of the OCC-3 proof transport. The example reads ONE transfer frame from stdin and materializes the decoded bytes through the shared owner-only no-replace Windows publisher (`examples/support/owner_publish.rs`, reused unchanged; no other file changes). The frame is the exact approved two-block protocol: an ASCII header `N=<canonical unsigned decimal><SP>H=<64 lowercase hex><LF>` capped at 77 bytes, then exactly `4*((N+2)/3)` unwrapped base64 characters, then EOF - no payload newline, whitespace, marker or trailing byte; the per-class decoded cap (challenge 4096, checkpoint 8192, descriptor 65536) is enforced BEFORE the payload is read or allocated, N=0 is syntactically valid but every class refuses it semantically, and base64 decoding is strict-canonical (alphabet, pad count, zero dropped bits). Expected length and digest are REQUIRED separate trusted caller inputs and must match the header AND the decoded bytes (three-way equality; the header is framing, never authorization). The destination is a validated absolute drive-letter Windows path (ASCII printable, no traversal) plus a FIXED class/name mapping - exactly one filename component per class at the journal root, no caller names or subpaths - and the staging-path budget (root + separator + name + 42 <= 230 UTF-16 units) is checked after argument parsing and BEFORE any filesystem open. Existing finals are refused by the shared primitive (no byte-idempotency is invented: `publish_refused_no_replay`), failed publications leave no staging residue, bytes are materialized verbatim with no JSON reserialization, digests verify content only (never destination), non-Windows fails closed, and stdout carries only a sanitized value-free status (class, name, byte count, digest). Explicitly NOT implemented in this phase (future launcher/helper under separate gates): SSH transport, network, identity/incarnation checks, current-state gates, the DGX-side placement helper, the staging receipt, orchestration - the example documents the authenticated-binding and current-state checks as the caller's future responsibility.

Tested: 19 embedded offline tests cover the exact frame round-trip and size boundaries (1, 2, 3, 4, 57, 58, 59, 100, cap), the machine-generated cap table (5541/11001/87461/349605/2796281), class-cap overflow proven refused before any payload read (trap reader), the 78-byte oversized header, 8-digit N, malformed integers (leading zero, sign, empty, non-digit), malformed hex (uppercase, 63/65 chars, non-hex), noncanonical whitespace (CR, double space, tab), non-UTF-8 header bytes, malformed/noncanonical base64 (`QR==` class), wrong trusted length/digest/content digests (the tamper arm asserts the original encoded byte, mutates it to a genuinely different valid-alphabet character, and keeps the trusted/header hashes at the original values), truncation and trailing data, N=0 semantics, destination grammar (traversal, relative, missing drive, trailing separator, non-ASCII, control bytes), the path budget enforced before any open, fresh publication with readback, existing-final refusal with prior bytes unchanged, the DOCUMENTED residue contract of the shared no-replay path (exactly one unchanged final plus exactly one private, INELIGIBLE `.{final}.{32 hex}.staging` residue - never published as a final; preserve-on-uncertainty semantics of the shared primitive preserved, no cleanup invented), and no side effects on every validation failure.
