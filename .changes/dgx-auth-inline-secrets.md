- Fixed `dgx-auth export` writing non-portable auth files when models.json credentials are command-backed: `"!"`-prefixed apiKey and header values (provider headers, model-level headers, and the gateway headers derived from them) are now resolved to their inline command output before the file is written, so exported files are self-contained on the recipient's machine.
- `dgx-auth export` now refuses to write a file when a command-backed credential cannot be resolved (helper fails, times out, or prints nothing), naming only the provider id and field kind and never the command or its output.
- `dgx-auth import` now rejects auth files that still contain `"!"`-prefixed apiKey or header values, naming the provider ids only, since importing them would leave the recipient's requests depending on the sharer's local helper commands.
