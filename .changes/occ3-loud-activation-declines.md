- Fixed silent OCC-3 activation declines. When a session's model declares an enabled `occ3` block and `agentCommunication.occ3Enabled` and `occ3Experimental` are both off, or the activation credentials do not resolve, the daemon log now records `occ3 activation declined reason=<code> session=<id> detail="..."`. The policy line names both settings keys. Sessions on ordinary models keep the off-by-default contract: no network and no log line. Before this change, the missing `occ3_handoff` tool was the only symptom. This was seen on a DGX deployment on 2026-11-10: settings.json had no OCC-3 keys, so every OCC-3 child started without the tool.
- Changed `/occ status` to name the settings decline when the selected model is OCC-3 configured but no native connector is live. `/occ 3 on` now returns a warning instead of a bare success when settings.json would still decline activation. Both messages name the exact keys and change no settings.
- Fixed the sglang-occ3 enroll quota leak. `BrokerAuthority` now drops expired session enrollments before its quota and identity checks, as `LatentRegistry.enroll` already did. Before, the table kept expired permits for the life of the server process. After `max_records` enrollments, every new enroll returned `quota` (HTTP 429) until the server restarted, and renewing a session whose permit had expired returned an identity conflict. Either refusal made the client decline activation, so no `occ3_handoff` tool was installed. Live enrollments keep every guard. The permit clock can be injected (`epoch=`), like the registry clock.
