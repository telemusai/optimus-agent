- Added `patches/dsa-mtp-seed.v1.json`, a backport of upstream sgl-project/sglang#42565 for `dsa_backend.py`, `index_topk_share.py` and `forward_mha.py`. With fused top-k, a ragged prefill's MTP seed is now mapped from logical flattened-KV offsets to physical KV slots before the first draft decode reads it. Before this, the first draft decode after a long cached-prefix prefill could read the wrong KV or past the pool.
- Packaging is not wired yet: `native_package.prepare` still accepts exactly three manifests, and the five DSA files are not in `source-baseline-expanded.json`. The image build therefore does not apply this manifest until that wiring lands. A MODE=full rebuild is required once it does.
- Fixed an OCC-3 consume whose rewritten prompt exceeds the DSA indexer top-k (GLM-5.3: 2048) getting admitted and issued a completed-use receipt while its injected prefix rows could be dropped from sparse attention. If the indexer pin is not active, the admit preflight now declines it pre-use with `profile`. The check is rank-uniform and runs inside `validate()`, before any mutation. `WorkerRuntime.dsa_pin_active` defaults to False. While the pin is active, `_flag_sparse_topk` only logs.
- Added `patches/dsa-pin.v1.json`. `Indexer._mask_init_and_local_tokens` now takes an optional per-row OCC-3 pin, read from `forward_batch.occ3_dsa_pin` as int32 start, count and a pin-hit counter. It forces `[start, start+count)` into the top-k at the paged, ragged and ragged-chunk call sites. Rows with count 0, and batches without the attribute, are bitwise unchanged. Not done yet: the producer that fills `occ3_dsa_pin` from `occ3_worker_descriptor`, the static graph-runner buffers, rank-0 settle logging, and setting `dsa_pin_active`. Until these land, over-top-k consumes keep declining.
