- Added `patches/dsa-mtp-seed.v1.json`, a backport of upstream sgl-project/sglang#42565 for `dsa_backend.py`, `index_topk_share.py` and `forward_mha.py`. With fused top-k, a ragged prefill's MTP seed is now mapped from logical flattened-KV offsets to physical KV slots before the first draft decode reads it. Before this, the first draft decode after a long cached-prefix prefill could read the wrong KV or past the pool.
- Added the DSA indexer pin for OCC-3 consumes. `patches/dsa-pin.v1.json` forces each attached consume row's injected prefix span `[prefix_offset, prefix_offset + expected_prefix_tokens)` (at most 128 positions) into the indexer top-k at the paged, ragged and ragged-chunk call sites. The pin plan is built once per forward. Each indexer layer then runs three small kernels (gather, fill, scatter). Batches without a pinned row skip the pin path, and unpinned rows stay bitwise unchanged.
- `ForwardBatch.init_new` builds `occ3_dsa_pin` from `batch.reqs` by batch index for every chunk and decode step of an attached request (in `scheduler-cache-ipc.v1.json`). The draft runner builds it in the shifted draft row space, so an eager draft step 0 that runs its own indexer uses the draft pin.
- A row is pinned only while its sequence can exceed `index_topk`: `len(origin_input_ids) + len(output_ids) + margin > index_topk`, where margin is twice the EAGLE draft-token width (this forward's rows plus one overlap-scheduling step; 2 without speculation). The inputs are rank-uniform host ints and static config. At or below the top-k the indexer already keeps every key, so a short consume carries no pin and its batch keeps the ordinary graphs. A receiver that grows past the top-k during decode is pinned from the crossing step. Settle requires pin-hit evidence only for a consume whose committed length exceeds `index_topk`; the producer rule is weaker, so such a consume was always pinned on its last target forward.
- The original CUDA graphs never carry the pin: the prefill, decode/target-verify, EAGLE draft and draft-extend graphs are captured with `occ3_dsa_pin` None, exactly as before. Ordinary batches replay them with no pin work.
- Pinned graph variants (in `capture-eager-mtp.v1.json`): the decode/target-verify, EAGLE draft-decode and draft-extend runners capture a second graph per batch size right after the unpinned one, in the same capture session and graph memory pool, keyed by the same `ShapeKey` with `variant_label="occ3_pin"`. Its capture batch carries a static `dsa_pin.GraphPin` view (int32 `start`/`count`/`forced` of length max_bs); the indexer rebuilds its plan inside capture (equal first layer id), so the recorded kernels read the static buffers. Replay of a pinned batch zeroes the buffers, copies the live pin (target space, or draft space with shift 1), replays the pinned variant and copies `forced` back. A load mismatch notes a fault, leaves count 0 (equal to unpinned) and does not raise; the request then fails at settle. `can_run_graph` takes the pinned variant only when every decode-family runner has one for the batch's padded size (`dsa_pin.graph_ok`, a function of the host row count and static capture lists), so target, draft and draft-extend agree; otherwise the pinned batch runs eager in all of them, as before. Pinned prefill chunks still run eager (no pinned prefill graph).
- Switches: `OCC3_DSA_PIN_GRAPHS=0` disables the pinned set (no GraphPin, no extra capture; behaviour equals the previous eager-only state). `OCC3_DSA_PIN_GRAPH_MAX_BS=<n>` limits the pinned bs list; the default is the full capture list. The pinned set is also skipped for runners with disabled padding, DP MLP gather, compact ragged verify or PD multiplexing.
- Cost (estimate from DGX TP0 logs; not measured with the pinned set): 26.4 GB free after the KV pool; capture uses about 1.8 GB prefill, 1.96 GB target verify (bs 1..32, 6 tokens per request), 0.7+0.29 GB draft decode and 1.65+0.29+0.60 GB draft extend, leaving about 18.4 GB. The pinned set roughly duplicates the decode-family graphs: about 5-6 GB more and about 1 minute more capture time. Reduce with `OCC3_DSA_PIN_GRAPH_MAX_BS` if headroom is short.
- Candidate-image check (N7): with `SGLANG_LOG_DECODE_GRAPH_KEY=1`, a verify step of an over-top-k receiver must log `Decode graph replay: occ3 pinned variant=occ3_pin` followed by the usual replay line, and ordinary steps must log no pinned line. Also measure decode ITL with one long-output receiver co-batched, and run TP8.
- If the pin is inactive at install, rank 0 logs one warning naming the failing stage (`topk`, `eagle_topk`, `attestation`, `manifests`, `import`, `members`, `headroom`).
- Pin code never raises on the shared scheduler or forward path. If the pin cannot be built or applied, it logs once, the forward runs unpinned, and a process fault counter is incremented. At terminal settle, a consume whose sequence exceeds the indexer top-k must show pin-hit evidence on every rank: a recorded forced count of at least `expected_prefix_tokens`, and no pin fault since admission. Otherwise that request fails through the existing `commit_failed` abort path (which also clears `occ3_force_eager`) and gets no completed-use receipt. Other requests are unaffected. Terminal settle also logs the pin-hit count on rank 0.
- Known limitation (upstream seed sharing): on the first draft decode after prefill, the draft reads the target-space seed, so draft row `offset - 1` is missing from that one step's selection until draft-extend republishes a draft-space seed.
- `dsa_pin_active` is True only when the attested source lists the `dsa-pin`, `scheduler-cache-ipc` and `capture-eager-mtp` manifests, the patched members import, the model has an integer `index_topk` above 128, `index_init_tokens + index_local_tokens + 128 <= index_topk`, `get_dsa_mtp_topk_width(config) == index_topk` when MTP IndexShare is on, and `speculative_eagle_topk` is 1. Any miss leaves the pin uninstalled, and over-top-k consumes then decline pre-use. The value must match on every rank.
- Fixed an OCC-3 consume whose rewritten prompt exceeds the DSA indexer top-k (GLM-5.3: 2048) being admitted and given a completed-use receipt while its injected prefix rows could be dropped from sparse attention. With the pin active, such consumes are admitted and pinned. Without it, the admit preflight declines them pre-use with `profile`.
- The image build applies five manifests (`native_package.prepare` accepts 1 to 16), and the five DSA source files are in `source-baseline-expanded.json`. A MODE=full rebuild is required to pick up the pin.

## D: extension-side state-well placement (LAYOUT_LAST_USER)

- A receiver consume whose rendered prompt has no `<<occ3-statebegin>>` marker no longer prepends the continuous prefix at row 0. The extension now places it immediately after the last user-turn role token of the rendered GLM prompt (`prefix_layout.LAYOUT_LAST_USER`). The role token is found by exact token-id match. Its id comes from the tokenizer's own attestation: `span_markers.resolve_user_role_id` requires `<|user|>` to encode to exactly one id and decode back to the same spelling. There is no text search. For text prompts, the same prefix-stability proof as the marker path applies: the decoded head must be a strict text prefix, and its encoding must equal `ids[:offset]`. The prompt is then pinned to those ids.
- An explicit marker still wins. If the role token cannot be attested, is absent, is the last token, or the proof fails, the legacy prepend layout runs. `PrefixLayout.fallback` then carries a bounded reason (`no_tokenizer`, `no_role_token`, `role_absent`, `unstable`, `shape`), and the plugin metrics count `prefix_layout_<kind>` and `prefix_layout_fallback_<reason>`.
- `ConsumeWorkerDescriptor` gains `prefix_layout` (default `prepend`, validated against the offset). The admit consensus value and the terminal record now report the real layout instead of deriving it from `offset > 0`. `descriptor.prefix_offset` carries the new offset, so the DSA pin start (`dsa_pin.pin_rows`) follows it unchanged. This is a deliberate behaviour change: receivers that relied on implicit prepend now get mid-sequence placement. The calibrated dual-ridge artifact is layout-independent (see /tmp/occ3-dsa/IMPL-D.md).
